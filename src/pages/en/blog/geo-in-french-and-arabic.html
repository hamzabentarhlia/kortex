  • Google recommends a different URL for each language version and says each version must list itself and every other version in its hreflang annotations.
  • Google works out a page's language from its visible content, not from the lang attribute. Use one language per page.

Buyers ask in their own language

A French-speaking buyer in Casablanca, Lyon or Montreal types the long question in French. An Arabic-speaking buyer types it in Arabic, or in a mix of languages. The assistant answers from sources it can retrieve in that language, so the shortlist the buyer reads depends on which sites have something to say in it. A site with an excellent English blog and no French or Arabic pages is, for these questions, absent.

Before any decision, measure the gap. Take your ten core buyer questions, write them natively in each language, and run them in the engines your buyers use. Log who is cited, as described in how to measure AI citations. The result is your own baseline, and it is likely to differ from English.

Separate URLs and reciprocal hreflang

Google's guidance on multilingual sites recommends using a different URL for each language version rather than using cookies or browser settings to change the language of a page. It then asks you to tell Google about the versions with hreflang annotations. The rules that cause most errors are short.

Hreflang rules from Google's documentation, and how to check them

Our own sitemap carries the annotations for English, French, Arabic and x-default on every page that exists in all three, and a page that exists in fewer languages lists only the ones it has. Google says it is acceptable to omit some languages on some pages as long as the versions that do exist point to each other. The point of the check is to catch the quiet failure, where the French page points to English and English does not point back, and the tags are ignored.

Write natively, do not translate mechanically

A translation that preserves words and loses the way a buyer would ask is the common failure. The question in English is "which approach to supplier risk works for a mid-size manufacturer". Nobody writes the French or Arabic equivalent that way, and a literal translation produces a page that answers a question nobody asks.

Our practice is to write the English first and then rewrite each language natively, starting from the questions as a native speaker would put them. For French that means writing to the reader as vous and avoiding English sentence structures. For Arabic it means choosing a register that fits the audience, and checking that technical terms are the ones practitioners use.

A translation answers the English question. A native page answers the one the buyer actually asks.

There is also a policy reason. Google lists "automated transformations like synonymizing, translating, or other obfuscation techniques" among the ways scaled content is generated where little value is provided to users. Localized versions are not duplicates when the main content is translated, so a real translation is fine. A machine pass with no review is the part that carries the risk, and the human QA layer is how we address it.

One language per page

Google determines the language of a page from the visible content and does not use code-level language information such as the lang attribute. It advises using a single language for content and navigation on each page and avoiding side-by-side translations. Translating only the navigation and footer while leaving the body in one language can create a bad experience, because the page then mixes languages.

Keep the lang attribute correct anyway, because browsers and screen readers use it, and set dir="rtl" on Arabic pages.

Latin names inside Arabic text

Brand names such as KORTEX, n8n or Odoo appear in Latin script inside right-to-left sentences. Without isolation, punctuation and neighbouring words can reorder around them. Wrapping each Latin run in a bdi element keeps it intact, and keeping the same Latin spelling in every language preserves the entity. We apply this on our Arabic pages.

Keep entities stable across scripts

An entity has to stay recognizable across languages. Keep the company name in the same Latin spelling everywhere, even inside Arabic text. Keep the founder's name in one transliteration per script and use it on every page. Define the key terms of your method once per language, in a glossary entry, so the French and Arabic versions point at the same concept and not at three different ones. The reasoning is in entity SEO for founders.

Let people choose, do not choose for them

Google advises against automatically redirecting users from one language version to another, for example on a guess about their language. Such redirects can prevent users and search engines from seeing all versions. Offer visible links between the versions on every page, and use the x-default annotation for a page that serves as the language selector.

Measure each language separately

Run the ten questions in each language monthly and keep one log per language. Compare citation rates by language and by engine. If the French rate is zero and the English rate is not, the likely causes are the ones in this article: no page, a page that does not answer the native question, missing hreflang, or a page that is not indexed. The GEO Audit Checklist covers indexing, sitemap and structured data checks, which apply to each language version in the same way.

Common questions about GEO in French and Arabic

Do I need separate pages for each language?

Yes. Google recommends a different URL for each language version, with hreflang annotations linking them, instead of changing the language of a page with cookies or browser settings.

Is translated content treated as duplicate content?

Google says localized versions are only considered duplicates if the main content stays untranslated.

Does the lang attribute tell Google the page language?

No. Google determines language from the visible content. Keep the attribute correct for browsers and screen readers, and write one language per page.

Can I use machine translation?

As a first pass followed by a native review, yes. Published without review it risks low-value pages, which Google's spam policy treats as scaled content abuse in some cases.

Should I redirect visitors to their language automatically?

Google advises against it. Give visible links to the other versions and let the visitor choose.

Will French and Arabic pages be cited by AI engines?

We cannot promise it. Run your core questions in each language monthly and log the results to see where you stand.
