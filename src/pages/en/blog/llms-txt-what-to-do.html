Key takeaways
  • llms.txt is a proposal, not a standard. It is a markdown file with one required element: an H1 with the site name.
  • Its author says it is mainly used by agents that fetch pages on demand, most heavily for software documentation.
  • Google says Search does not use llms.txt, and that publishing one will neither help nor harm visibility in Google Search.
  • We publish one anyway, generated from the same files as the site, because it costs almost nothing and some tools read it.
  • We do not sell it as a citation tactic. We have no evidence that it moves citations in ChatGPT, Perplexity or Gemini.

What llms.txt is

llms.txt is a plain markdown file placed at the root of a website, at /llms.txt. It gives a language model a short, curated map of the site: what it is, and where the useful pages are.

The proposal is published at llmstxt.org. It asks site owners to add the file, and to offer clean markdown versions of pages at the same address with .md added. The idea is simple. A web page wraps its content in navigation, scripts and layout. An agent that wants the content has to strip all of that off, and the result is imprecise. A small file that points straight at clean text saves the agent that work.

The file has a fixed shape, in this order:

  • An H1 with the name of the site. This is the only required part.
  • A blockquote with a short summary.
  • Optional paragraphs or lists with more detail, but no headings.
  • Sections under H2 headings that hold lists of links. Each link can carry a short note after a colon.

By convention, a section called "Optional" holds secondary links an agent can skip when it needs a shorter context.

What the proposal claims, and what it does not

The current version describes itself as version 2 and says it is based on two years of adoption. It reports that thousands of sites publish the file, that documentation platforms generate it automatically, and that Chrome's Lighthouse checks for it as part of its agentic browsing checks. It also notes that OpenAI, Anthropic and Gemini publish llms.txt files for their own developer documentation.

Read what that does and does not say. It says the file exists and is read in some workflows. It says the use is heaviest for software documentation, where a coding agent follows the links to find an API reference. It does not say that publishing one makes a model more likely to cite your site in an answer. The author's own expectation is that the file is useful at inference time, when an agent needs something on demand, and mainly not for training.

The proposal also states how it relates to older files. A sitemap lists every page for search engines. llms.txt offers a curated overview. robots.txt says what automated tools may access. llms.txt is used when an agent is already allowed in and needs context. They do different jobs, and one does not replace the other.

What Google says about it

Google is direct. In its guide to generative AI features in Search, it lists llms.txt files among the things you can ignore for Google Search. Its wording: you do not need to create new machine-readable files, AI text files, markup or markdown to appear in Google Search, including its generative AI features, because Google Search itself does not use them.

It then adds a sentence worth reading twice. Creating and maintaining an llms.txt file for other services is fine, and doing so will neither harm nor help your visibility or rankings in Google Search, because Google Search ignores it.

That settles one question and leaves another open. For Google Search, the answer is clear. For everything else, such as ChatGPT, Perplexity and the many agents that browse on behalf of users, there is no equivalent public statement that we could find and open. Absence of a statement is not evidence in either direction.

Where the claims go too far

You will see llms.txt sold as a way to get cited by AI engines. We have not seen a controlled test that shows this, and the proposal itself does not make the claim. Three things are worth separating:

  • The file exists and some tools read it. True, according to the proposal.
  • Reading it changes what a model says about you. Unproven.
  • Not having one costs you citations. Unproven, and Google says it does not matter for its own Search.

If a vendor quotes a lift in citations from adding the file, ask for the method: which prompts, how many runs, which engines, and what else changed in the same weeks. Without that, the number is a story.

What we do on this site

We publish a file at /llms.txt. It has a title, a short description of what KORTEX does, the three plans with their prices, our key pages, and lists of every glossary entry, comparison and article. It also points to the French and Arabic versions.

We do not write it by hand. The site builder generates it from the same source files as the pages, so the prices and page descriptions in the file cannot drift from the pages. When a price changes on the site, the file changes in the same build.

We keep it because it costs almost nothing, a person can read it in a minute, and some tools do fetch it. We do not report it to clients as a result, and we do not put it in a plan as a deliverable that moves rankings.

The effort that does matter sits elsewhere. Pages have to be indexed and eligible to show a snippet. Our robots.txt allows the crawlers of the main AI engines on public pages. Important content is in plain HTML text, so it is readable without running scripts. The content has something specific to say. That is where a month of effort is better spent than on a text file.

How to write a good one if you decide to

  1. Start with the H1 and a two-sentence summary that says what you do and for whom, with no adjectives.
  2. List the pages you would want an agent to read first. Ten to thirty links is plenty for a company site.
  3. Add a short note after each link that says what is on the page.
  4. Put secondary material under an "Optional" heading.
  5. Generate it from your content source rather than editing it by hand, so it stays true.
  6. Check it every time a price, plan or page changes.

When to skip it

Skip it if nobody will own it. A stale llms.txt that lists retired pages or old prices is worse than no file, because it gives a model wrong information with the confidence of a curated list. If you cannot generate it from your real content, do not publish it.

Common questions about llms.txt

Is llms.txt an official standard?

No. It is a proposal published at llmstxt.org. It is not an IETF or W3C standard. Some documentation platforms generate it and some tools read it, but no body governs it.

Does Google use llms.txt?

No. Google states that Google Search does not use llms.txt files, and that having one will neither help nor harm your visibility or rankings in Google Search.

Will llms.txt get me cited by ChatGPT or Perplexity?

We have no evidence that it does. The proposal does not claim it, and we found no public test showing it. Treat any promised lift with caution and ask for the method behind it.

Where does the file go?

At the root of the site, at /llms.txt. The proposal also allows the file at a subpath, such as /docs/llms.txt, where it covers the pages under that path.

What is the difference between llms.txt and robots.txt?

robots.txt tells automated tools what they may access. llms.txt gives an agent that is already reading your site a curated overview and links. The first is about permission, the second is about guidance.

Should I list every page?

No. The point is curation. List the pages you would want an agent to read first, and use the sitemap for the full list.
